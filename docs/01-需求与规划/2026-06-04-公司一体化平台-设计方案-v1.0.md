# 公司一体化平台设计方案

## 一、项目概述

公司一体化平台定位为公司内部统一应用门户，用于集中管理和展示公司相关系统、项目地址、小程序入口、账号凭据、系统状态与访问说明。员工登录平台后，可在首页快速检索并访问被授权的系统入口；管理员可在后台统一维护项目卡片、弹窗内容、账号密码、二维码、状态检测和权限范围。

平台核心目标包括：

- 建立统一入口，减少员工在浏览器书签、聊天记录、文档中查找系统地址的成本。
- 通过项目卡片和分类导航，清晰展示公司内部系统、客户项目、AI 工具、数据平台、运维服务、小程序等资源。
- 点击项目卡片后，以弹窗形式集中展示 Web 地址、账号密码、小程序二维码、系统状态、使用说明和维护联系人。
- 支持按部门、角色和用户授权控制项目可见范围与账号密码查看权限。
- 通过自动检测与人工覆盖结合的方式展示系统是否可用，辅助员工判断系统访问状态。
- 通过后台管理能力，让项目入口和弹窗内容可维护、可审计、可持续更新。

本方案推荐采用“自建账号登录 + 权限版应用门户 + 自动状态检测 + 后台配置管理”的 MVP 路线，优先满足公司内部真实使用场景，并为后续接入统一身份认证或单点登录预留空间。

## 二、功能范围

### 2.1 前台门户

前台门户面向公司员工和被授权用户，提供统一登录后的系统入口访问能力。

- 登录与退出：用户使用平台账号和密码登录，登录后进入门户首页。
- 项目卡片展示：按分类展示项目卡片，卡片包含项目 Logo、项目名称、分类、当前状态等信息。
- 分类筛选：支持按内部系统、客户项目、AI 工具、数据平台、运维服务、小程序等分类查看。
- 关键词搜索：支持按项目名称、简称、标签、描述快速检索。
- 项目详情弹窗：点击卡片后打开弹窗，展示系统地址、账号凭据、小程序二维码、状态详情、访问说明和维护联系人。
- 权限化展示：用户只能看到被授权的项目卡片和弹窗内容。

### 2.2 后台管理

后台管理面向管理员、项目管理员和部门管理员，用于维护门户展示内容和访问权限。

- 用户管理：维护平台登录账号、姓名、手机号、部门、角色、启用状态和密码重置。
- 部门管理：维护公司组织部门，用于项目可见范围控制。
- 角色管理：维护超级管理员、项目管理员、部门管理员、普通员工、访客等角色。
- 项目卡片管理：维护项目名称、Logo、分类、排序、标签、简介、启用状态和首页展示样式。
- 弹窗内容管理：维护 Web 地址、账号密码、小程序二维码、使用说明、维护人、备注等信息。
- 状态检测管理：配置自动检测地址、检测方式、检测频率、超时时间、期望状态码和人工覆盖状态。
- 权限配置：控制项目可见范围、密码查看权限、复制权限和二维码查看权限。
- 操作日志：记录登录、打开弹窗、查看密码、复制密码、后台修改、状态检测等关键行为。

### 2.3 状态检测

状态检测采用“自动检测为主 + 管理员人工覆盖”的方式。

- 默认使用 HTTP/HTTPS 检测项目 Web 地址是否可达。
- 支持 TCP 端口检测，用于部分非标准 Web 服务。
- 支持 ping 作为辅助检测项，但不作为唯一判断依据。
- 支持管理员手动设置维护中、异常、正常、未检测等状态。
- 支持立即检测和定时检测，MVP 阶段建议默认每 5 分钟检测一次。
- 前台首页展示当前状态标识和状态汇总，详情弹窗展示最近检测时间、响应耗时和异常原因。

### 2.4 权限与审计

平台权限分为“项目可见权限”和“敏感信息查看权限”两类。

- 无项目权限：前台不展示对应项目卡片。
- 有项目权限但无密码权限：可查看地址、二维码、状态和说明，不可查看密码。
- 有密码权限：可查看和复制账号密码。
- 管理员权限：可维护项目、凭据、二维码、状态检测、权限和日志。
- 查看密码、复制密码、修改凭据等敏感行为必须记录日志。

## 三、核心模块设计

### 3.1 登录与账号体系

平台采用自建账号登录。用户由管理员在后台创建或导入，登录密码仅保存加密哈希，不保存明文密码。用户登录成功后，系统根据用户所属部门、角色和额外授权计算可访问的项目范围。

登录模块应支持：

- 账号密码登录。
- 登录失败次数限制。
- 首次登录或密码重置后修改密码。
- 账号启用、停用和锁定。
- 登录日志记录。

### 3.2 门户首页

门户首页是员工使用频率最高的页面，应优先保证检索效率和信息密度。页面采用类似参考图的卡片式布局，但每张卡片需要增加状态标识，并在点击后打开项目详情弹窗。

卡片展示内容建议包括：

- 项目 Logo。
- 项目名称。
- 项目简称。
- 项目分类。
- 状态标识：可用、异常、维护中、未检测。
- 项目简介摘要。
- 可选标签：正式、测试、内网、外网、小程序等。

首页交互建议包括：

- 顶部搜索框支持关键词搜索。
- 左侧或顶部分类筛选。
- 支持状态筛选和状态概览。
- 卡片点击默认打开弹窗，不直接跳转项目地址。

### 3.3 项目详情弹窗

项目详情弹窗用于承载项目访问所需的完整信息，是本平台的核心交互。

弹窗内容建议分区展示：

- 基本信息：项目名称、Logo、简介、分类、标签、维护联系人。
- 系统状态：当前状态、最近检测时间、响应耗时、异常原因。
- 访问地址：正式地址、测试地址、后台地址、文档地址等多地址列表。
- 账号凭据：用户名、密码、账号说明、适用环境、过期时间。
- 小程序入口：二维码图片、二维码说明、适用人群。
- 访问说明：浏览器要求、VPN 要求、网络说明、注意事项。

密码默认隐藏。用户具备密码查看权限时，可点击“显示密码”并复制；无权限时仅展示无权查看提示。所有查看和复制行为都需要写入审计日志。

### 3.4 后台项目管理

后台项目管理用于维护首页卡片和弹窗内容。项目管理员可以创建项目并补充访问资料，超级管理员可管理全部项目。

项目管理字段建议包括：

- 项目名称、简称、Logo、分类、标签、排序。
- 项目简介、启用状态、首页是否展示。
- 维护部门、维护人、联系方式。
- 可见部门、可见角色、额外授权用户。
- 是否允许查看密码、是否允许复制密码、是否允许查看二维码。

### 3.5 凭据与二维码管理

项目账号密码和小程序二维码属于敏感或重要访问资料，应独立管理。

- 一个项目可配置多组账号密码。
- 每组账号可绑定适用环境，例如正式环境、测试环境、演示环境。
- 密码应加密存储，前端仅在用户具备权限且主动查看时返回。
- 二维码支持上传、替换、预览和停用。
- 凭据修改、二维码替换需要记录操作人和操作时间。

### 3.6 状态检测模块

状态检测模块负责定时检测项目地址是否可达，并将检测结果反馈给首页卡片和详情弹窗。

检测逻辑建议：

- 优先使用 HTTP/HTTPS 请求检测 Web 地址。
- 对 `200`、`302`、`401`、`403` 等可预期响应判定为服务可达。
- 对 `500`、`502`、`503`、`504`、DNS 失败、连接超时、证书异常等判定为异常。
- 对无法通过 HTTP 判断的服务，可配置 TCP 端口检测。
- ping 可作为辅助检测方式，但不能作为唯一可用性依据。
- 管理员人工设置“维护中”时，前台优先展示人工状态。

## 四、数据结构与流转

### 4.1 关键数据实体

平台建议至少包含以下核心数据实体：

- 用户：保存登录账号、姓名、手机号、部门、角色、账号状态、密码哈希等信息。
- 部门：保存部门名称、上级部门、排序、启用状态等信息。
- 角色：保存角色名称、角色编码、权限集合和启用状态。
- 项目：保存项目名称、Logo、分类、标签、简介、排序、启用状态、维护人等信息。
- 项目地址：保存项目关联的正式地址、测试地址、后台地址、文档地址等。
- 项目凭据：保存项目账号、加密后的密码、适用环境、账号说明、启用状态。
- 小程序二维码：保存项目二维码图片、说明、适用范围、启用状态。
- 项目权限：保存项目与部门、角色、用户之间的可见和敏感信息权限关系。
- 检测配置：保存检测方式、检测地址、频率、超时时间、期望状态码、人工覆盖状态。
- 检测记录：保存每次检测结果、响应耗时、错误原因、检测时间。
- 操作日志：保存用户登录、查看弹窗、查看密码、复制密码、后台修改等行为。

### 4.2 前台访问数据流

用户登录平台后，系统按以下流程返回门户数据：

1. 用户提交平台账号和密码。
2. 后端验证账号状态和密码哈希。
3. 登录成功后生成会话或令牌。
4. 后端根据用户部门、角色和额外授权计算项目可见范围。
5. 前台请求项目列表，后端仅返回用户有权查看的项目卡片。
6. 用户点击项目卡片，前台请求项目详情。
7. 后端根据权限返回地址、二维码、状态和说明。
8. 若用户无密码权限，后端不返回明文密码。
9. 若用户点击查看密码，后端再次校验权限，记录日志后返回解密后的密码。

### 4.3 后台管理数据流

管理员维护项目时，系统按以下流程保存配置：

1. 管理员登录后台。
2. 创建或编辑项目基础信息。
3. 配置项目地址、账号凭据、小程序二维码和访问说明。
4. 配置项目可见部门、可见角色、额外授权用户。
5. 配置密码查看和复制权限。
6. 配置状态检测方式、检测地址和人工覆盖状态。
7. 系统保存配置并记录后台操作日志。
8. 前台门户根据最新配置展示项目卡片和弹窗内容。

### 4.4 状态检测数据流

状态检测任务按配置定时执行：

1. 定时任务读取启用自动检测的项目。
2. 根据项目检测配置选择 HTTP、TCP 或 ping 检测方式。
3. 发送检测请求并记录响应状态、耗时和错误原因。
4. 根据检测规则生成自动检测状态。
5. 若项目存在人工覆盖状态，前台优先展示人工状态。
6. 若无人工覆盖状态，前台展示自动检测状态。
7. 检测结果在项目卡片和详情弹窗中同步展示。

## 五、边界情况与安全策略

### 5.1 网络与检测边界

- 如果项目必须在公司内网或 VPN 环境下访问，检测服务应优先部署在可访问这些系统的网络环境中。
- 如果检测服务无法访问某项目，但员工浏览器可访问，应允许关闭自动检测或使用人工状态维护。
- 如果目标系统禁用 ping，不应直接判定系统不可用。
- 如果项目登录页返回 `401` 或 `403`，但服务本身可达，可判定为可用。
- 如果项目存在多个地址，应允许选择一个地址作为检测地址，也可分别检测多个地址。

### 5.2 密码与敏感信息安全

- 平台登录密码只保存哈希，不能保存明文。
- 项目访问密码应加密存储，普通列表接口不得返回明文密码。
- 查看密码必须由用户主动触发，并进行权限校验。
- 查看和复制密码必须记录日志。
- 后台导出功能不应默认导出明文密码。
- 对离职、调岗或账号停用用户，应立即失效其平台访问权限。

### 5.3 权限边界

- 项目可见权限和密码查看权限必须分开控制。
- 用户同时命中多个权限规则时，建议采用“授权取并集、敏感操作按更严格规则校验”的策略。
- 项目管理员只能维护自己负责的项目，不能越权查看其他项目凭据。
- 部门管理员只能维护本部门授权范围内的用户和项目。
- 超级管理员可维护全部项目，但敏感操作仍需记录审计日志。

### 5.4 前台交互边界

- 无权限项目不在首页展示，避免泄露项目存在信息。
- 有项目权限但无密码权限时，弹窗中显示“无权限查看密码”，不展示掩码后的真实字段。
- 项目异常时，仍允许用户查看地址和说明，便于判断是否为网络、浏览器或 VPN 问题。
- 二维码图片缺失时，弹窗应显示未配置提示，不影响地址和账号信息展示。
- 状态检测时间过久时，应显示“检测结果可能已过期”。

### 5.5 MVP 实施范围

第一阶段建议实现以下能力：

- 自建账号登录。
- 用户、部门、角色基础管理。
- 项目卡片管理。
- 项目详情弹窗配置。
- 项目地址、账号密码、小程序二维码维护。
- 按部门和角色控制项目可见范围。
- 按权限控制密码查看和复制。
- HTTP/HTTPS 自动状态检测。
- 管理员人工设置维护中或异常。
- 查看密码、复制密码、后台修改日志。

第二阶段可扩展：

- 多检测点或内网检测节点。
- 项目批量导入。
- 密码到期提醒。
- 更细粒度的字段级权限。
- 企业微信、钉钉、LDAP 或统一身份认证接入。
- 单点登录改造，减少共享账号密码使用。

### 5.6 推荐落地顺序

推荐按以下顺序推进：

1. 先完成需求规格说明书，明确页面、字段、权限和状态规则。
2. 设计前台门户首页和项目详情弹窗原型。
3. 设计后台项目管理、凭据管理、权限配置页面原型。
4. 完成数据库表结构和接口设计。
5. 开发登录、权限、项目管理和前台门户。
6. 开发状态检测任务和检测结果展示。
7. 补充审计日志、安全策略和测试用例。
8. 导入第一批公司项目数据并试运行。
