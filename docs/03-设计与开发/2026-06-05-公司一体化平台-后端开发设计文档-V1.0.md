# 公司一体化平台后端开发设计文档

## 一、文档目标

本文档用于把公司一体化平台的 SRS 需求、功能清单和已完成前端 Mock 页面转换为后端开发可执行蓝图。后续后端开发可依据本文档拆分模块、设计数据库表、实现接口、编写测试用例并推进前后端联调。
！
本文档重点回答以下问题：

| 问题 | 文档内对应章节 |
|---|---|
| 后端需要建设哪些业务模块 | 三、后端模块总览；四、模块详细设计 |
| 每个模块覆盖哪些功能清单条目 | 三、后端模块总览；四、模块详细设计 |
| 数据库需要哪些表，表之间如何关联 | 五、数据库设计 |
| 前端已经预留了哪些真实接口路径 | 六、接口设计与联调清单 |
| 权限、密码、日志、检测任务怎么做 | 七、关键业务流程；八、安全与权限设计；九、状态检测设计 |
| 后端开发应该按什么顺序推进 | 十一、开发任务拆解 |

## 二、设计输入与建设假设

### 2.1 设计输入

| 来源 | 作用 |
|---|---|
| SRS 需求规格说明书 | 提供项目范围、业务角色、详细业务规则、数据实体、非功能要求 |
| 功能清单 | 提供 45 个页面级功能点、优先级和建设类型 |
| 交付计划 | 确认前端 Phase 1 已完成，后端进入 Phase 2 接口联调准备 |
| `admin/src/api/*.ts` | 提供管理后台已预留的真实接口路径、请求方式和字段类型 |
| `website/src/api/portal.ts` | 提供前台门户已预留的真实接口路径和响应约定 |
| `admin/src/types/project.ts`、`website/src/types/project.ts` | 提供项目信息、地址、凭据、二维码、检测、日志等前端字段结构 |

### 2.2 当前工程状态

当前仓库包含两个前端工程：

| 工程 | 说明 |
|---|---|
| `admin` | 管理后台，已完成登录、系统管理、项目管理、状态检测、权限审计等 Mock 闭环 |
| `website` | 前台门户，已完成项目卡片和项目详情相关页面 |

当前仓库未发现独立后端工程目录。因此本文档按“后端从 0 到 1 建设，并与现有前端 API 口径对齐”的方式设计。

### 2.3 推荐后端技术栈

如果项目没有既定后端技术约束，建议采用以下技术栈：

| 层级 | 建议选型 | 说明 |
|---|---|---|
| 后端框架 | Java 17 + Spring Boot 3 | 当前项目位于 JavaProject 工作区，便于团队统一技术栈 |
| ORM | MyBatis Plus 或 Spring Data JPA | 以团队熟悉度为准，本文表设计不绑定具体 ORM |
| 数据库 | MySQL 8.x | 满足管理系统、权限、日志和状态检测记录需求 |
| 缓存 | Redis，可选 | 用于验证码、登录会话、权限缓存、检测任务锁 |
| 任务调度 | Spring Scheduler / Quartz | MVP 可用 Spring Scheduler，后续多节点可升级 Quartz 或分布式调度 |
| 文件存储 | 本地磁盘 / MinIO / 对象存储 | MVP 可本地存储，正式环境建议独立文件服务 |
| 鉴权 | JWT + 服务端会话校验 | 兼容前端 `Authorization: Bearer token` |

### 2.4 MVP 范围与后续增强

MVP 必须实现 P0 与 P1 功能，P2 作为预留设计：

| 优先级 | 范围 |
|---|---|
| P0 | 登录、用户部门角色、项目卡片、详情内容、凭据、二维码、状态检测、项目授权、密码权限、操作日志 |
| P1 | 人工状态覆盖 |
| P2 | 批量导入项目、密码到期提醒 |

P2 功能在数据库表中预留字段或扩展点，但不要求第一阶段完整开发。

## 四、模块详细设计

### 4.1 B01 认证与会话

**建设目标**

实现平台账号密码登录、验证码、Token 颁发、当前用户信息返回、登录失败限制和用户停用后的会话失效。

**覆盖功能**

| 功能清单 | 后端能力 |
|---|---|
| 登录 | 校验账号、密码、验证码、用户状态，颁发访问令牌 |
| 找回密码提示 | 后端可提供平台配置项，第一阶段前端可固定提示 |

**核心规则**

- 登录账号全局唯一。
- 停用、锁定用户不可登录。
- 连续登录失败达到阈值后锁定或临时限制。
- 用户停用后，应使现有 Token 失效。
- 平台用户密码只保存哈希，不保存明文。

**主要接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/captcha/image` | 获取图形验证码 |
| GET | `/api/captcha/verify` | 校验图形验证码 |
| POST | `/admin/login` | 管理后台登录 |
| GET | `/admin/user/info` | 获取当前登录用户信息、角色、部门、按钮权限 |
| POST | `/admin/logout` | 登出，建议新增 |
| POST | `/admin/token/refresh` | 刷新 Token，建议新增 |

**开发任务**

| 序号 | 任务 | 验收标准 |
|---|---|---|
| B01-01 | 建立用户密码哈希与登录校验 | 正确账号可登录，错误账号不可登录 |
| B01-02 | 实现验证码生成与校验 | 验证码一次性或短时有效 |
| B01-03 | 实现 JWT 颁发和解析 | 前端 `Authorization: Bearer token` 可访问受保护接口 |
| B01-04 | 实现当前用户信息接口 | 返回用户、部门、角色、按钮权限 |
| B01-05 | 实现登录日志 | 成功和失败都写入操作日志 |

### 4.2 B02 组织与用户管理

**建设目标**

维护平台用户、部门层级和用户状态，为登录、项目授权和后台操作权限提供主体数据。

**覆盖功能**

| 功能清单 | 后端能力 |
|---|---|
| 用户筛选、列表、新增、编辑、重置密码、启用/停用 | 用户 CRUD、分页查询、状态控制 |
| 部门列表、新增、编辑、启用/停用 | 部门树、层级维护、停用校验 |

**核心规则**

- 用户账号全局唯一。
- 新增用户时初始密码必须符合复杂度要求。
- 停用用户后不可登录，当前会话应失效。
- 停用部门时，如果部门下存在启用用户，应阻止停用或要求先调整用户。
- 删除用户建议第一阶段采用逻辑删除。
- 部门删除前应校验子部门、用户、授权记录。

**主要接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/organization/user/list` | 查询用户列表 |
| POST | `/admin/organization/user/add` | 新增用户 |
| PUT | `/admin/organization/user/{id}` | 编辑用户 |
| DELETE | `/admin/organization/user/{id}` | 删除用户 |
| POST | `/admin/organization/user/batch-delete` | 批量删除用户 |
| PUT | `/admin/organization/user/{id}/status` | 更新用户状态 |
| PUT | `/admin/organization/user/{id}/reset-password` | 重置密码 |
| POST | `/admin/organization/user/batch-set-role` | 批量设置角色 |
| GET | `/admin/organization/department/list` | 查询部门树 |
| POST | `/admin/organization/department/add` | 新增部门 |
| PUT | `/admin/organization/department/{id}` | 编辑部门 |
| DELETE | `/admin/organization/department/{id}` | 删除部门 |
| PUT | `/admin/organization/department/{id}/status` | 更新部门状态 |

**开发任务**

| 序号 | 任务 | 验收标准 |
|---|---|---|
| B02-01 | 建立用户、部门、用户角色关联表 | 可保存组织和用户基础数据 |
| B02-02 | 实现部门树查询和部门状态控制 | 前端部门管理页面可联调 |
| B02-03 | 实现用户分页、筛选、新增、编辑 | 前端用户管理页面可联调 |
| B02-04 | 实现重置密码和停用用户 | 停用用户无法继续登录 |
| B02-05 | 实现批量角色设置 | 多用户角色分配正确写入 |

### 4.3 B03 角色与菜单权限

**建设目标**

维护后台角色、菜单、按钮权限，为管理后台菜单显示和接口权限校验提供依据。

**覆盖功能**

| 功能清单 | 后端能力 |
|---|---|
| 角色列表、新增、编辑、启用/停用 | 角色 CRUD、状态控制 |
| 角色权限配置 | 角色菜单授权、按钮权限返回 |

**核心规则**

- 内置角色包括超级管理员、项目管理员、部门管理员、普通员工、访客用户。
- 角色停用后不可分配给新用户。
- 已分配停用角色的用户，权限计算时不应继续生效。
- 超级管理员可拥有全部后台菜单和按钮权限。
- 菜单权限控制页面入口，按钮权限控制新增、编辑、删除、导出等操作。

**主要接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/permission/role/list` | 查询角色列表 |
| POST | `/admin/permission/role/add` | 新增角色，当前前端一个文件使用该路径 |
| POST | `/admin/permission/role` | 新增角色，当前前端另一个文件使用该路径 |
| PUT | `/admin/permission/role/{id}` | 编辑角色 |
| DELETE | `/admin/permission/role/{id}` | 删除角色 |
| PUT | `/admin/permission/role/{id}/status` | 更新角色状态 |
| GET | `/admin/permission/role/{id}/menus` | 查询角色菜单权限 |
| PUT | `/admin/permission/role/{id}/menus` | 更新角色菜单权限 |
| PUT | `/admin/permission/role/{id}/permissions` | 分配角色权限，需与前端统一 |
| GET | `/admin/permission/menu/list` | 查询菜单树 |

**联调注意**

`admin/src/api/organization.ts` 与 `admin/src/api/permission.ts` 中角色新增和角色授权路径存在重复口径。后端可临时兼容两套路径，但正式联调前建议统一为 REST 风格：

- 新增角色：`POST /admin/permission/role`
- 更新角色菜单：`PUT /admin/permission/role/{id}/menus`

### 4.4 B04 项目主数据

**建设目标**

维护前台项目卡片展示所需的项目基础资料，是项目地址、凭据、二维码、权限、检测配置和日志的主表。

**覆盖功能**

| 功能清单 | 后端能力 |
|---|---|
| 项目筛选、列表、新增、编辑、删除、启用/停用 | 项目 CRUD、分页筛选、启停控制、删除校验 |

**核心规则**

- 项目名称全局唯一。
- 项目可配置简称、Logo、分类、标签、简介、维护人、排序。
- 停用项目后前台不展示，但后台保留历史配置和日志。
- 删除项目前必须校验关联数据，包括地址、凭据、二维码、检测配置、授权、日志。
- 项目状态由状态检测模块维护，项目表保留当前展示状态冗余字段。

**主要接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/project/options` | 项目下拉选项 |
| GET | `/admin/project/list` | 分页查询项目卡片 |
| POST | `/admin/project` | 新增项目 |
| PUT | `/admin/project/{id}` | 编辑项目 |
| DELETE | `/admin/project/{id}` | 删除项目 |
| PUT | `/admin/project/{id}/enabled` | 启用或停用项目 |

**开发任务**

| 序号 | 任务 | 验收标准 |
|---|---|---|
| B04-01 | 建立项目主表和标签存储策略 | 项目基础信息可保存 |
| B04-02 | 实现项目列表分页和筛选 | 支持关键词、分类、维护人、启用状态、项目状态 |
| B04-03 | 实现新增编辑项目 | 项目名称重复时返回明确错误 |
| B04-04 | 实现项目启停 | 停用项目不会在门户展示 |
| B04-05 | 实现删除校验 | 有关联数据时阻止删除 |

### 4.5 B05 项目详情内容

**建设目标**

维护项目详情弹窗中展示的访问地址、浏览器要求、VPN 要求、注意事项和维护联系人。

**覆盖功能**

| 功能清单 | 后端能力 |
|---|---|
| 地址维护 | 项目多地址保存、默认地址、检测地址标记 |
| 说明维护 | 浏览器要求、VPN 要求、注意事项、维护联系人 |

**核心规则**

- 一个项目可维护多个访问地址。
- 每个项目最多一个默认打开地址。
- 每个项目可有一个或多个用于检测的地址，MVP 可限制为最多一个检测地址。
- 地址停用后前台不展示。
- 项目详情中地址和说明只对项目可见用户返回。

**主要接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/project/{projectId}/detail-content` | 查询项目详情维护内容 |
| PUT | `/admin/project/{projectId}/addresses` | 保存项目地址列表 |
| PUT | `/admin/project/{projectId}/instruction` | 保存项目访问说明 |

### 4.6 B06 项目凭据安全

**建设目标**

维护项目账号凭据，加密存储项目密码，并在用户具备权限时支持查看和复制。

**覆盖功能**

| 功能清单 | 后端能力 |
|---|---|
| 账号维护 | 凭据新增、编辑、停用、删除 |
| 查看密码 | 权限校验、解密、审计 |
| 复制密码 | 权限校验、解密、审计 |
| 密码权限 | 授权规则计算 |

**核心规则**

- 项目访问密码必须加密存储。
- 普通凭据查询只返回 `passwordMasked`，不得返回明文密码。
- 查看密码、复制密码必须服务端重新校验权限。
- 查看密码、复制密码应先写入操作日志，日志成功后再返回明文或复制内容。
- 日志中不保存明文密码，只保存凭据名称、项目、操作类型和结果。
- 凭据停用后前台不展示。
- 到期时间字段作为 P2 密码到期提醒预留。

**主要接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/project/credential/list` | 查询凭据列表 |
| POST | `/admin/project/credential` | 新增或保存凭据 |
| DELETE | `/admin/project/credential/{id}` | 删除凭据 |
| PUT | `/admin/project/credential/{id}/status` | 更新凭据状态 |
| POST | `/admin/project/credential/{id}/reveal` | 查看后台凭据密码 |
| POST | `/admin/project/credential/{id}/copy` | 复制后台凭据用户名或密码 |
| POST | `/app/portal/credentials/{id}/reveal` | 建议新增，门户查看密码 |
| POST | `/app/portal/credentials/{id}/copy` | 建议新增，门户复制账号或密码 |

**安全实现建议**

| 项 | 建议 |
|---|---|
| 平台用户密码 | BCrypt 或 Argon2 哈希 |
| 项目凭据密码 | AES-GCM 加密，密钥从环境变量或密钥服务读取 |
| 明文返回 | 只在 reveal/copy 接口短暂返回 |
| 日志 | 记录操作者、项目、凭据、操作类型、IP、设备、结果 |
| 权限 | 先校验项目可见，再校验 `passwordView` 或 `passwordCopy` |

### 4.7 B07 项目二维码与文件

**建设目标**

支持项目 Logo 和小程序二维码等文件上传、预览、替换、停用和访问控制。

**覆盖功能**

| 功能清单 | 后端能力 |
|---|---|
| 二维码维护 | 上传、替换、预览、停用 |
| 项目 Logo | 项目卡片图片上传和访问 |

**核心规则**

- 上传文件必须限制类型和大小。
- Logo 建议支持 `jpg`、`jpeg`、`png`、`webp`。
- 二维码建议支持 `jpg`、`jpeg`、`png`。
- 文件保存后记录文件名、路径、大小、类型、上传人、上传时间。
- 二维码停用后前台不展示。
- 替换二维码时保留历史文件记录，业务表指向最新启用文件。

**主要接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/admin/file/upload` | 通用文件上传，建议新增 |
| GET | `/admin/project/qrcode/list` | 查询二维码列表 |

### 4.8 B08 状态检测

**建设目标**

维护项目检测配置，支持定时检测、立即检测、人工覆盖状态和检测记录查询。

**覆盖功能**

| 功能清单 | 后端能力 |
|---|---|
| 检测配置列表、编辑、立即检测 | 配置管理、手动触发检测 |
| 人工状态 | 人工覆盖状态与原因 |
| 检测记录查询、详情 | 检测历史、耗时、错误原因 |

**核心规则**

- 自动检测只检测启用项目。
- 人工覆盖状态优先于自动检测结果展示。
- 人工状态为维护中时，自动检测继续记录，但不覆盖前台展示状态。
- 立即检测不改变检测频率，只新增检测记录。
- HTTP/HTTPS 返回 `200`、`302`、`401`、`403` 可判定为服务可达。
- HTTP/HTTPS 返回 `500`、`502`、`503`、`504` 判定异常。
- DNS 失败、连接超时、证书异常、连接被拒绝判定异常。
- 检测结果超过配置频率两倍未更新时，前台提示检测结果可能过期。

**主要接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/status/config/list` | 查询检测配置 |
| PUT | `/admin/status/config/{id}` | 更新检测配置 |
| POST | `/admin/status/config/{id}/run` | 立即检测 |
| PUT | `/admin/status/config/{id}/manual-status` | 设置人工状态 |
| GET | `/admin/status/record/list` | 查询检测记录 |

### 4.9 B09 项目授权

**建设目标**

按部门、角色、用户配置项目可见、密码查看、密码复制和二维码查看权限。

**覆盖功能**

| 功能清单 | 后端能力 |
|---|---|
| 项目权限配置授权 | 授权规则 CRUD |
| 密码权限 | `passwordView`、`passwordCopy` 规则 |

**核心规则**

- 授权对象类型包括部门、角色、用户。
- 用户同时命中多条授权规则时，项目可见权限取并集。
- 敏感权限建议按显式授权计算，未授权默认拒绝。
- 如果项目不可见，则无论是否配置密码权限，都不得返回详情和凭据。
- 项目管理员只能维护自己负责项目或被授权管理的项目。

**主要接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/audit/project-permission/list` | 查询项目授权配置 |
| POST | `/admin/audit/project-permission` | 保存项目授权 |
| DELETE | `/admin/audit/project-permission/{id}` | 删除项目授权 |

**权限计算建议**

1. 获取当前用户 ID、部门 ID、角色 ID 列表。
2. 查询启用的项目授权规则。
3. 匹配授权对象为当前用户、当前部门或任一角色的规则。
4. 项目可见取并集。
5. 密码查看、密码复制、二维码查看按命中规则聚合；MVP 可采用“任一规则允许即允许”，如需更严格可增加拒绝规则优先级。
6. 返回门户项目列表时只查询可见项目。

### 4.10 B10 门户访问

**建设目标**

为前台门户提供授权项目卡片列表、项目详情、地址打开、复制地址、查看密码、复制密码和二维码查看能力。

**覆盖功能**

### 4.12 B12 操作日志与审计

**建设目标**

记录登录、打开项目详情、查看密码、复制密码、修改项目资料、修改授权、立即检测、人工状态变更等关键行为，支持查询和导出。

**覆盖功能**

| 功能清单 | 后端能力 |
|---|---|
| 操作日志查询 | 分页查询、按用户、项目、操作类型、结果、时间范围筛选 |
| 操作日志导出 | 导出当前筛选结果，不包含明文密码 |

**核心规则**

- 查看密码、复制密码、修改凭据、修改授权必须记录日志。
- 日志记录失败时，不影响非敏感信息查看；但查看密码和复制密码应在日志成功后返回结果。
- 普通员工只能查看与自己相关的日志摘要。
- 项目管理员只能查看负责项目相关日志。
- 超级管理员可查看全部日志。
- 日志默认保留不少于 180 天。
- 导出数据过多时应提示缩小筛选范围。

**主要接口**

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/audit/operation-log/list` | 查询操作日志 |
| GET | `/admin/audit/operation-log/export` | 导出操作日志 |

**建议的日志采集方式**

| 类型 | 实现方式 |
|---|---|
| 登录成功、失败 | 登录服务显式写日志 |
| 查看密码、复制密码 | 凭据服务显式写日志，作为返回明文前置步骤 |
| 后台新增、编辑、删除、启停 | 使用审计切面或业务服务统一记录 |
| 状态检测 | 立即检测和人工覆盖显式写日志，自动任务可写检测记录 |

### 4.13 B13 通用基础能力

**建设目标**

为所有业务模块提供统一响应、分页、异常处理、参数校验、文件访问、字典枚举、审计上下文和数据权限基础能力，减少各业务模块重复实现。

**核心能力**

| 能力 | 说明 |
|---|---|
| 统一响应 | 所有接口返回统一 `code`、`message`、`data`、`success`、`timestamp` |
| 统一异常 | 业务异常、参数异常、权限异常、系统异常分别映射为明确错误码 |
| 参数校验 | 对新增、编辑、查询参数做后端校验，错误信息可直接展示给前端 |
| 分页封装 | 统一返回 `list`、`total`、`page`、`pageSize` |
| 当前用户上下文 | 从 Token 解析当前用户、部门、角色、权限 |
| 数据权限上下文 | 为项目授权、日志查询、后台项目管理提供数据范围判断 |
| 字典枚举 | 维护用户状态、项目状态、项目分类、检测方式、凭据环境、操作类型 |
| 文件访问 | 管理文件上传、下载、预览 URL 和存储路径 |
| 审计上下文 | 统一提取 IP、User-Agent、操作者、操作对象 |

**开发任务**

| 序号 | 任务 | 验收标准 |
|---|---|---|
| B13-01 | 定义统一响应和分页模型 | 前端能稳定解析所有接口 |
| B13-02 | 定义业务异常和错误码 | 重复、无权限、参数错误等能返回明确提示 |
| B13-03 | 定义登录用户上下文工具 | 业务服务无需重复解析 Token |
| B13-04 | 定义字典枚举常量 | 前后端枚举值保持一致 |
| B13-05 | 定义审计辅助工具 | 日志记录能自动带出 IP、设备和操作者 |

## 六、接口设计与联调清单

### 6.1 统一响应结构

管理后台当前 HTTP 封装以 `code === 200` 判定成功，建议后端统一返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "success": true,
  "timestamp": 1780646400000
}
```

分页响应建议统一为：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "list": [],
    "total": 0,
    "page": 1,
    "pageSize": 10
  },
  "success": true,
  "timestamp": 1780646400000
}
```

联调前必须处理一个差异：`website/src/api/portal.ts` 当前以 `code !== 0` 判定失败，而 `admin` 以 `code === 200` 判定成功。建议将 `website` 改为兼容 `200`，或后端对门户接口临时返回 `0`。从全局一致性看，推荐统一为 `200`。

### 6.2 错误码建议

| code | 说明 | 典型场景 |
|---|---|---|
| 200 | 成功 | 请求成功 |
| 400 | 业务错误 | 参数非法、重复数据、状态不允许 |
| 401 | 未登录或 Token 失效 | Token 缺失、过期 |
| 403 | 权限不足 | 无菜单权限、无项目权限、无密码权限 |
| 404 | 数据不存在 | 项目、用户、凭据不存在 |
| 409 | 数据冲突 | 项目名称重复、账号重复 |
| 500 | 服务异常 | 未预期异常 |

## 七、关键业务流程

### 7.1 登录流程

1. 前端获取验证码。
2. 用户输入账号、密码、验证码。
3. 后端校验验证码。
4. 后端查询用户，校验用户状态。
5. 后端校验密码哈希。
6. 登录失败时增加失败计数并记录日志。
7. 登录成功时清空失败计数，生成 Token，记录登录成功日志。
8. 前端携带 Token 调用 `/admin/user/info` 获取用户、角色、部门和权限。

### 7.2 后台维护项目流程

1. 管理员登录后台。
2. 后端校验菜单和按钮权限。
3. 管理员新增或编辑项目主数据。
4. 后端校验项目名称唯一性。
5. 后端保存项目主表。
6. 管理员维护地址、说明、凭据、二维码。
7. 后端保存对应子表，并记录后台修改日志。
8. 项目启用后，可被状态检测和授权模块引用。

### 7.3 门户项目详情流程

1. 用户登录门户。
2. 后端根据用户、部门、角色计算可见项目 ID。
3. 门户查询项目卡片列表。
4. 用户点击项目卡片。
5. 后端再次校验项目可见权限。
6. 后端聚合项目主数据、地址、说明、二维码、状态信息、权限标记。
7. 后端记录打开项目详情日志。
8. 前端展示详情弹窗。

### 7.4 查看或复制密码流程

1. 用户在门户或后台点击查看密码或复制密码。
2. 后端查询凭据并校验凭据状态。
3. 后端校验项目可见权限。
4. 后端校验密码查看或复制权限。
5. 后端写入操作日志，日志内容不包含明文密码。
6. 日志写入成功后，后端解密密码并返回。
7. 前端短时展示或写入剪贴板。

### 7.5 状态检测流程

1. 定时任务查询启用项目的启用检测配置。
2. 根据检测方式执行 HTTP/HTTPS、TCP 或 ping。
3. 记录检测结果、响应耗时、错误原因。
4. 更新检测配置当前状态。
5. 若无人工覆盖或人工覆盖过期，更新项目主表当前状态。
6. 前台项目列表和详情读取项目状态展示。

### 7.6 操作日志导出流程

1. 管理员输入筛选条件。
2. 后端校验日志查看权限和数据范围。
3. 后端校验导出数量上限。
4. 后端查询日志并过滤敏感字段。
5. 后端生成导出数据。
6. 后端记录导出日志。

## 八、安全与权限设计

### 8.1 权限分层

| 权限层 | 控制对象 | 示例 |
|---|---|---|
| 登录权限 | 是否可进入平台 | 用户启用、停用、锁定 |
| 菜单权限 | 是否可进入后台页面 | 用户管理、项目管理、状态检测 |
| 按钮权限 | 是否可执行后台操作 | 新增、编辑、删除、导出 |
| 数据权限 | 能看到哪些业务数据 | 项目管理员只能维护负责项目 |
| 项目可见权限 | 门户能看到哪些项目 | 部门、角色、用户授权 |
| 敏感权限 | 能否查看或复制密码 | `passwordView`、`passwordCopy` |

### 8.2 敏感数据处理

| 数据 | 存储策略 | 返回策略 |
|---|---|---|
| 平台登录密码 | 哈希存储 | 永不返回 |
| 项目访问密码 | 对称加密存储 | 普通查询返回脱敏值，查看接口按权限返回明文 |
| 验证码 | Redis 或内存短时存储 | 校验后失效 |
| Token | 前端保存，后端校验签名和状态 | Token 失效时返回 401 |
| 操作日志 | 不保存明文密码 | 可查询、可导出，但不包含敏感明文 |

### 8.3 接口安全要求

- 所有 `/admin/**` 接口默认要求登录。
- 所有 `/app/portal/**` 接口默认要求登录。
- `/api/captcha/**` 和 `/admin/login` 可匿名访问。
- 后端必须做权限过滤，不能只依赖前端隐藏按钮。
- 文件上传接口必须校验登录态、文件类型、文件大小。
- 异常响应不得暴露堆栈信息。
- 导出接口必须校验权限和导出上限。

## 九、状态检测设计

### 9.1 检测方式

| 检测方式 | 输入 | 判定规则 |
|---|---|---|
| HTTP/HTTPS | URL、超时时间、期望状态码 | 命中期望码或 200、302、401、403 判定可用 |
| TCP | 地址、端口、超时时间 | 端口可连接判定可用 |
| ping | 主机、超时时间 | 仅作辅助，目标禁 ping 时不直接判定业务不可用 |
| 手动 | 人工状态 | 不自动检测，前台展示人工状态 |

### 9.2 任务调度

MVP 可用单实例定时任务：

| 任务 | 频率 | 说明 |
|---|---|---|
| 检测任务扫描 | 每 1 分钟 | 找出到期需要检测的配置 |
| 项目状态检测 | 按配置频率 | 默认 5 分钟 |
| 人工覆盖过期处理 | 每 5 分钟 | 到期后恢复自动检测状态 |
| 历史检测记录清理 | 每天凌晨 | 默认保留 90 天 |

多节点部署时，需要增加分布式锁，避免同一项目被多个节点重复检测。

### 9.3 状态展示优先级

1. 项目停用：前台不展示。
2. 人工覆盖未过期：展示人工状态。
3. 有最近自动检测结果：展示自动检测状态。
4. 无检测结果：展示未检测。
5. 最近检测时间超过配置周期两倍：状态可继续展示，但详情提示检测结果可能已过期。

## 十二、联调前必须统一的事项

| 事项 | 当前情况 | 建议 |
|---|---|---|
| 响应成功码 | `admin` 期望 `200`，`website` 期望 `0` | 统一为 `200`，修改 `website` 请求封装 |
| 门户路径 | `admin` 使用 `/app/portal/*`，`website` 使用 `/api/portal/*` | 统一为 `/app/portal/*` |
| 角色新增路径 | `/admin/permission/role/add` 与 `/admin/permission/role` 并存 | 统一为 `/admin/permission/role`，后端短期兼容 |
| 角色授权路径 | `/menus` 与 `/permissions` 并存 | 统一为 `/menus` 或调整前端调用 |
| 登录参数位置 | `fetchLogin` 当前用 `params` 发 POST | 建议改为 JSON body，后端短期兼容 query 参数 |
| 项目凭据字段 | `admin` 使用 `passwordMasked`，`website` 类型中有 `password` | 门户普通详情不返回 `password`，仅 reveal 接口返回明文 |
| 分页字段 | 项目接口使用 `{ list, total }` | 后端可同时返回 `page`、`pageSize`，兼容现有前端 |

## 十三、后端开发完成定义

后端达到可进入测试验收的标准如下：

| 检查项 | 完成标准 |
|---|---|
| 接口完整性 | 本文 P0 接口全部实现，P1 人工状态覆盖按计划实现 |
| 数据库 | 表结构、索引、唯一约束、初始化数据可重复部署 |
| 权限 | 菜单权限、按钮权限、项目可见权限、密码权限均在服务端生效 |
| 安全 | 平台密码哈希，项目密码加密，日志不含明文密码 |
| 状态检测 | 定时检测、立即检测、人工覆盖、检测记录可用 |
| 日志 | 登录、查看密码、复制密码、后台修改、导出等关键行为可追溯 |
| 前端联调 | `admin` 和 `website` 可关闭 Mock 使用真实接口 |
| 测试 | 核心业务单元测试、接口测试、权限测试通过 |
| 部署 | 提供后端启动配置、数据库初始化脚本、文件存储配置说明 |
